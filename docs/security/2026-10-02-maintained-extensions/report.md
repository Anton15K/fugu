# Maintained public MCP and skill audit — 2 October 2026

**No vulnerability was independently verified in this audit.** Six maintained public projects were pinned and reviewed within the scope below. Fugu's frozen concealment and static stages scanned 44 selected files, producing zero alerts. An existing filesystem metadata-confinement lead remains unreproduced. No vulnerability issue drafts were created.

This result covers source inspection and two deterministic Fugu stages. It does not establish that these projects are safe. Execution confirmation was interrupted by a native runtime cybersecurity block reported by the lead; the affected work was not resumed through another model or agent. Independent review of this bounded report is pending.

The following leads remain separate from confirmed vulnerabilities:

- **Filesystem listing metadata:** At `f46d9578190b476b3501923ea8977d899e8db2cb`, the `list_directory_with_sizes` handler validates the requested directory, then calls a symlink-following stat on each child. It reports the resulting size. This differs from the documented restriction to configured directories and from the realpath check used for ordinary file access. A pre-existing link inside an allowed root is the relevant prerequisite; arbitrary file contents or symlink creation through an MCP tool were not demonstrated. The source supports an already-known metadata-confinement concern, but there is no observed unauthorized effect from this audit, no assigned severity, and no claim of a new issue. [Handler, lines 483–537](https://github.com/modelcontextprotocol/servers/blob/f46d9578190b476b3501923ea8977d899e8db2cb/src/filesystem/index.ts#L483), [validation, lines 140–183](https://github.com/modelcontextprotocol/servers/blob/f46d9578190b476b3501923ea8977d899e8db2cb/src/filesystem/lib.ts#L140), [directory contract](https://github.com/modelcontextprotocol/servers/blob/f46d9578190b476b3501923ea8977d899e8db2cb/src/filesystem/README.md#L59). Upstream [PR #4732](https://github.com/modelcontextprotocol/servers/pull/4732) was open and unmerged at retrieval. Its proposed non-following metadata lookup is an existing remediation proposal, not our reproduced fix. Fugu S0/S1 emitted no alert on the affected handler.
- **Skill evaluation XML:** At `8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4`, mcp-builder's `parse_evaluation_file` uses the standard ElementTree parser. Upstream [issue #58](https://github.com/anthropics/skills/issues/58) and open, unmerged [PR #1837](https://github.com/anthropics/skills/pull/1837) propose hardened XML parsing. Runtime parser protections, resource bounds and an attacker-controlled evaluation-file path were not verified here. This remains a known hardening/inconclusive lead; no XML exploit or denial of service was observed. [Parser, lines 61–82](https://github.com/anthropics/skills/blob/8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4/skills/mcp-builder/scripts/evaluation.py#L61). Fugu S0/S1 emitted no alert. The separately inspected docx entrypoint already imports hardened ElementTree, so the repository cannot be described as uniformly using unsafe XML parsing. [Docx entrypoint](https://github.com/anthropics/skills/blob/8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4/skills/docx/scripts/office/validate.py#L22).

Several apparently broad capabilities have explicit contracts and were not promoted to vulnerability claims:

- Reference Fetch documents internal-address access. Its robots handling is not an internal-network authorization boundary. Open [issue #4838](https://github.com/modelcontextprotocol/servers/issues/4838) requests restrictions; this audit did not demonstrate a violation of a promised network restriction. [Pinned Fetch warning](https://github.com/modelcontextprotocol/servers/blob/f46d9578190b476b3501923ea8977d899e8db2cb/src/fetch/README.md#L12).
- MarkItDown-MCP accepts file, data and HTTP resources for trusted local use. Its README describes the process privileges, absence of authentication and default loopback binding; the entrypoint warns when another bind address is selected. Reading a file within those privileges alone does not establish unauthorized access. [Pinned security contract](https://github.com/microsoft/markitdown/blob/2b61a335a4bec721144498fe425a61f23e9e3d6e/packages/markitdown-mcp/README.md#L132), [entrypoint](https://github.com/microsoft/markitdown/blob/2b61a335a4bec721144498fe425a61f23e9e3d6e/packages/markitdown-mcp/src/markitdown_mcp/__main__.py). Existing [issue #1905](https://github.com/microsoft/markitdown/issues/1905) was open; its allegation was not independently confirmed here.
- Playwright's pinned README treats origin and file guards as convenience defenses and directs users to client permissions for isolation. A documented limitation is not evidence of a violated security promise. The wrapper delegates execution to playwright-core; its exact dependency was recorded, but core/browser behavior was excluded from the performed scan. [Pinned access-control contract](https://github.com/microsoft/playwright-mcp/blob/f183dad4a52965583e3cc1d59b88cdc279e2e57d/README.md#L783), [security note](https://github.com/microsoft/playwright-mcp/blob/f183dad4a52965583e3cc1d59b88cdc279e2e57d/README.md#L823).

Negative source observations also have narrow limits. GitHub's inventory filter rejects tools lacking a read-only annotation when read-only mode is enabled, and its lockdown author check returns an error or restricted result when the cache/author/lookup is unavailable. This supports the inspected design; it is not a runtime test of every tool annotation, transport or token permission. [Read-only filter](https://github.com/github/github-mcp-server/blob/36e5c48f2e376f8f4ffa30fd718c38deedb7ae27/pkg/inventory/filters.go#L38), [lockdown check](https://github.com/github/github-mcp-server/blob/36e5c48f2e376f8f4ffa30fd718c38deedb7ae27/pkg/github/lockdown.go#L23). Superpowers' companion source checks a session key on HTTP/WebSocket access, restricts file serving to regular files inside its content directory, and applies an owner-only startup umask. Neither unauthorized requests nor browser behavior were executed here. [Authentication](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/brainstorming/scripts/server.cjs#L339), [file guard](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/brainstorming/scripts/server.cjs#L304), [startup permissions](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/brainstorming/scripts/start-server.sh#L109).
