## Purpose and authorized scope

Current stage: written spec only, ready for human written-spec review and named independent review; no implementation or measured requests are authorized by this assignment.

The human wants to measure the cost of complete Fugu audits against a capable agent auditing the same repositories directly, and determine whether the agent is equally correct. The pilot has a **USD 10 total provider-cost ceiling**, not USD 10 per arm. Use the same Nebius-hosted Nemotron models. Run the actual complete system; isolated detector tests and fake provider responses are verification of the harness only and cannot be reported as measured audits. Deliver reproducible evidence, a report, per-case results and charts suitable for the jury. The outcome may favor either arm.

**Assumption:** security accuracy is the main Fugu claim; general functional bugs are a separate utility question. Local Docker execution is available only if native prerequisites pass. Model endpoint revisions can drift even when IDs match; record returned model IDs and timestamps. The pilot is descriptive and cannot prove statistical equivalence.

## Options and chosen approach

1. **Recommended: native production Fugu versus a direct tool-assisted auditor with the same Ultra/Super model availability.** Preserves production orchestration and measures the product as users run it. Report the different model allocations explicitly; this controls model availability, not identical token allocation.
2. All-Ultra Fugu versus an all-Ultra agent. Cleaner single-model causal comparison, but changes the native production profile. Defer this clearly labeled ablation until the native pilot shows its cost and the human authorizes additional spend.
3. A single prompt over repository excerpts. Cheap but not a credible agent or a complete audit; excluded from this experiment.

Both chosen arms share the same maximum spend per audit and input/tool opportunities. Record each normal workflow's actual cost inside that ceiling. This is an equal **budget ceiling**, not a claim that actual spends are identical or a full accuracy-versus-budget frontier.

## Direct-agent arm

Use a generic repository audit loop, independent of Fugu detection rules, stages, prompts, scores and outputs. Ultra is the principal auditor; an explicit Super second-pass review is required before a completed final answer. The Super reviewer can inspect the same tree and principal evidence but receives no truth labels or Fugu findings. The Ultra principal considers that critique and produces a structured final result. Both calls and their complete conversational histories count toward cost. Record their roles and model allocations.

The principal can list/read/search the entire same source snapshot, inspect manifests, query the same Tavily/OSV services and request execution in the same owned canary chamber. It can choose what to investigate and invoke; it is not given Fugu-generated triggers, probes, evidence or verdicts. Sharing the raw sandbox/collector implementation is allowed as an execution service; invoking Fugu's detectors is not. Runtime-required evidence is mandatory for a complete behavioral answer. The prompt asks for actionable issues supported by locations, mechanism, severity and proof, distinguishes suspicious text from behavior, and states the task and output format identically for security/utility lanes as appropriate.

Tool access is confined to the snapshot and chamber. No host shell for target code, outside credentials or hidden ground-truth paths. Tool results have explicit size/truncation metadata; truncated coverage is recorded. The generic loop has at most 32 outbound model attempts total per audit, including investigative Ultra turns, Super review/tool turns, Ultra finalization and every explicit recovery. Investigation stops by attempt 30 at the latest, leaving at least one Super critique and one Ultra finalization attempt; start review earlier if it needs more turns. Reserve room and money for critique/finalization rather than letting investigation consume them. Both model roles can request the same bounded tools, and Super may use multiple review turns inside that shared limit; every tool-result continuation needs a counted model attempt. Missing a completed critique or final answer at the limit makes the audit incomplete. Each call has a 4096 maximum output-token setting, temperature 0.1 and a 90-second timeout, matching production defaults; there are no hidden SDK retries. Endpoint billable-token limits remain separately verified as specified below. Exhausted turns, unavailable required tools, missing critique, malformed final results and unfinished audits are incomplete. Version and freeze the agent prompt and tool schemas before execution; independently review that it is a credible baseline.

## Accounting and money guard

One durable, process-locked ledger owns **all outbound paid requests in both arms**. Store immutable reservation, dispatch and settlement events separately from derived aggregate summaries; persist and flush each reservation before network dispatch. Never overwrite prior request evidence when settling or recovering. Reserve a conservative upper-bound USD amount on disk before dispatch; only release excess after valid provider usage settles it. Enforce settled cost plus all outstanding reservations at or below USD 10 globally, and USD 2 per audit. Reserve a USD 4 envelope before starting a pair, divided into two USD 2 arm envelopes, so the second arm is not starved by the first. Request reservations are carved from their arm envelope, never added on top of the already-reserved envelope. Settlement replaces request reservations with actual known cost, and unused arm capacity is released only after the pair is terminal. Invariant: prior settled liabilities plus the current pair envelope and any retained unknown liabilities never exceed USD 10; within each arm, settled cost plus outstanding request reservations never exceeds USD 2. This may stop conservatively before the full USD 10 is consumed. Unsettled reservations count against the cap across crashes/restarts. No concurrent ledger owners, automatic retry after orphaned requests, or unguarded network paths.

Use Decimal/integer microdollars with rounding upward. A model reserve must cover an authoritative input-token bound, maximum billable output including reasoning under the endpoint contract, and any separately priced cache/tool fees. If an exact tokenizer bound is unavailable, use the provider's documented total context limit as a conservative input reserve; verify output/context units rather than assuming them. Never infer a safe token maximum from a characters/4 heuristic. Refuse unknown models, unpriced services or requests whose upper bound cannot be established. Per-audit ceilings apply to reservations as well as settlements.

Capture actual input/output usage, requested and served model, response/request IDs when available, duration, retries, finish reasons and stage/member/agent-turn attribution. Avoid double charging duplicated fan-out evidence or cached replay; a new network dispatch always gets a new reservation. Preserve full tool-call messages in the agent journal and replay if supported; the historical RequestJournal's content-only response replay must not be blindly reused for agent tool calls. Disable SDK hidden retries and account every explicit recovery attempt. Unknown usage, timeout, error or crash retains its worst-case reservation and stops further paid dispatch until reviewed; never count it as zero.
