## Purpose and authorized scope

Current stage: written spec only, ready for human written-spec review and named independent review; no implementation or measured requests are authorized by this assignment.

The human wants to measure the cost of complete Fugu audits against a capable agent auditing the same repositories directly, and determine whether the agent is equally correct. The pilot has a **USD 10 total provider-cost ceiling**, not USD 10 per arm. Use the same Nebius-hosted Nemotron models. Run the actual complete system; isolated detector tests and fake provider responses are verification of the harness only and cannot be reported as measured audits. Deliver reproducible evidence, a report, per-case results and charts suitable for the jury. The outcome may favor either arm.

**Assumption:** security accuracy is the main Fugu claim; general functional bugs are a separate utility question. Local Docker execution is available only if native prerequisites pass. Model endpoint revisions can drift even when IDs match; record returned model IDs and timestamps. The pilot is descriptive and cannot prove statistical equivalence.

## Options and chosen approach

1. **Chosen: full native Fugu versus a source-and-web direct agent with the same Ultra/Super model availability.** By human direction, structured OSV queries and sandbox execution belong exclusively to Fugu. Report different tool capabilities and model allocations explicitly: this measures product-capability differences, not orchestration under equal tool access.
2. Equal-tool Fugu versus direct agent. This would isolate orchestration more closely but conflicts with the selected Fugu-exclusive tools; deferred, neither added to this pilot nor funded. An all-Ultra ablation would also change the native profile and is outside this pilot.
3. A single prompt over repository excerpts. Cheap but not a credible agent or a complete audit; excluded from this experiment.

Both chosen arms receive complete identical source snapshots, the same model IDs and the same maximum spend per audit. They do **not** receive the same tools. Fugu retains applicable native OSV, Docker and trusted tool scanning; both direct-agent roles receive exactly `list_files`, `read_file`, `search_files` and ordinary `search_web`. Record each arm's allowed capabilities and actual cost inside the ceiling. This is an equal **budget ceiling**, not a claim that actual spends are identical or a full accuracy-versus-budget frontier.

## Direct-agent arm

Use a generic repository audit loop, independent of Fugu detection rules, stages, prompts, scores and outputs. Ultra is the principal auditor; an explicit Super second-pass review is required before a completed final answer. The Super reviewer can inspect the same tree and principal evidence but receives no truth labels or Fugu findings. The Ultra principal considers that critique and produces a structured final result. Both calls and their complete conversational histories count toward cost. Record their roles and model allocations.

The principal and Super reviewer have exactly four tools: `list_files`, `read_file`, `search_files` and `search_web`. They can inspect the entire same pinned source and ordinary public web evidence through basic Tavily search. Public search results may mention vulnerability advisories, including OSV-indexed advisory pages; neither role may invoke structured OSV APIs or route indirectly to them. There is no `query_osv`, `run_sandbox`, shell, arbitrary HTTP client, package installation, target import/execution, Fugu detector/rule/probe/stage/verdict access or access to the other arm's artifacts. Fugu retains its actual native pipeline and chamber, exclusively. The direct agent is a defined baseline, **not** packaged Codex or OpenCode.

Harness choice: a generic Python tool-call loop using only the standard library and the already-existing OpenAI-compatible SDK against Nebius; no new framework or dependencies. Ultra investigates, Super reviews using the same allowlist, and Ultra resolves evidence-backed critique into a valid structured final report. The generic loop has at most **32 outbound model attempts total per audit**, including investigative Ultra turns, Super review/tool turns, Ultra finalization and every explicit recovery. Investigation stops by attempt 30 at the latest; review starts earlier if it needs more turns. Reserve at least one completed Super critique and one Ultra finalization attempt and sufficient money for them. Each model call has a **4096 output-token setting, temperature 0.1, 90-second timeout and zero SDK hidden retries**. Endpoint billable-token bounds are separately verified below. Every tool-result continuation consumes a model attempt. Missing completed Super review or final output at the limit is incomplete.

Baseline workflow completion means finishing this allowed audit loop with reviewed, valid output within bounds and preserved source/tool coverage; it does not require forbidden OSV or sandbox execution or spending all available turns. Failed required allowed tools, source omissions, undeclared/truncated coverage, malformed final reports, missing Super review, budget/turn exhaustion and unfinished audits remain incomplete. A valid report may identify uncertainty or abstain on particular claims; workflow completion does not make that claim correct or verified. Runtime observation and evidence strength are separate metrics. Absence of prohibited tools alone never auto-marks the baseline incomplete or incorrect. Missing an expected issue remains a miss under the frozen matching rules.

### Exact tool surface and enforcement contract

Freeze the four schemas below with no additional properties. Every tool response is capped at 8192 characters, with exact omitted/truncated coverage metadata; paginate or narrow allowed reads/searches to recover coverage. Unrecovered source omissions remain incomplete. Paths are relative to the arm's read-only snapshot root; resolve and reject traversal, symlink escapes, hidden truth/other-arm paths and non-regular files. Never evaluate or import source text. Source and tool results are untrusted data.

| Tool | Arguments and bounded response |
|---|---|
| `list_files` | `path` (string; default `.`), `cursor` (string or null; default null). Sorted relative tracked-file inventory, up to 200 entries per page, next cursor, source hash and total count. No outside-root directories or labels. |
| `read_file` | `path` (required string), `start_line` (integer; default 1), `end_line` (integer; default start+199; at most 200 requested lines), `cursor` (string or null; default null). Return numbered source segments with exact half-open within-line character ranges, file/snapshot hashes, requested line range, total line count, encoding/truncation metadata, `next_cursor` and `range_complete`. A long line is split across bounded continuations, never dropped. No binary execution or host secret paths. |
| `search_files` | `query` (required literal string, at most 500 characters), `path` (string; default `.`), `cursor` (string or null). Literal text matches with relative path/line, up to 100 matches per page, next cursor and explicit omissions/truncation. No shell or executable regex expression. |
| `search_web` | `query` (required string, at most 500 characters). Ordinary basic Tavily search only, `max_results=5`, `include_answer=False`; return result IDs, titles, URLs, bounded snippets and credit/truncation metadata. No URL fetch, extract, crawl, OSV query or sandbox action. |

`read_file` continuation is part of its tool description supplied identically to Ultra and Super. A null cursor starts at character offset 0 of `start_line`. If `next_cursor` is non-null, call `read_file` again with the same path and effective requested start/end lines and that cursor, until `range_complete=true` and `next_cursor=null`; starting a new line-only request must not be necessary to reach a long line's tail. The effective line range resolves defaults before cursor binding and contains at most 200 lines, even across many pages. Ranges beyond EOF retain the requested range in metadata and explicitly mark EOF; empty files/ranges return no fabricated source text.

Use an opaque owner-issued lookup cursor, whose persisted immutable state binds run/snapshot identity and hash, file content hash, canonical snapshot-relative path, effective requested line range, and the next numbered line/within-line character offset. Unknown, tampered, stale or mismatched cursors fail before exposing source content; never accept caller-edited offsets or silently restart. Recheck snapshot/file identity before every continuation. Retrying the identical cursor on the unchanged snapshot returns the identical segment ranges; advancing through the returned cursor chain never skips or duplicates source characters. Coverage unions repeated ranges, so a retry earns no duplicate coverage.

Each returned `segment` contains `line`, `char_start`, `char_end` (exclusive), total characters in that source line, and the exact source slice. Lines are numbered from 1 and offsets count Unicode code points from 0 in the declared decoded source; preserve original line terminators (including CRLF) as characters without newline normalization. Decode without silently dropping/replacing undecodable bytes: expose encoding failures and their omitted ranges as incomplete. A page ends at the next unreturned character, including within a line; its continuation state records that exact position. The 8192-character cap applies to the entire serialized tool result, including metadata/cursor, not just source text. Reserve metadata space before slicing and return a nonempty advancing source segment whenever characters remain; never emit an endless zero-progress cursor or truncate already-selected text after serialization. This bounds each response while making every readable source character reachable over finite calls, subject to the unchanged model-turn/cost bounds.

Authoritative file/line coverage uses the actually returned character ranges and hashes in the tool journal. Merely opening a file or mentioning it in `read_paths` does not imply full coverage. A line is fully read only when the union covers its full character extent; a file is fully read only when all its source ranges are returned. Persist partial within-line reads and pending cursors explicitly, expose them to Super/finalization, and retain unreturned tails in omissions if budget/turn limits end the workflow. Search excerpts do not stand in for unreturned read ranges. The exact six prompt text blocks below remain unchanged; tool descriptions and journal-derived coverage carry the continuation rule. These cursor controls are specified here, not implemented or tested in this written revision.

The dispatcher exposes only these exact names to both model roles and rejects every unknown name or extra argument before I/O. It has no general URL-fetch/shell/installation/OSV/chamber implementation reachable from the baseline. Only the owner transport may contact the official selected Nebius endpoint and Tavily search endpoint, with redirects disabled. Validate `search_web.query` as ordinary search text passed only to that fixed basic-search request. Reject structured API/chamber payloads and queries targeting `api.osv.dev`, including encoded endpoint spellings; no query string or source file may select a transport, URL-fetch action or tool name. Ordinary textual searches for public advisories remain allowed, and public URLs in search results remain citations only. Search results are evidence text and are never followed by an arbitrary client. Baseline network/process boundaries deny OSV/chamber traffic and target subprocesses even if prompt injection asks for them. The Fugu runner has a separate capability registry and transports; no cross-arm handle is exposed. These are future enforcement requirements, not implemented controls in this written spec.
