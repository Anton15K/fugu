# Maintained public MCP and skill vulnerability audit

Owner: research.security, coordinated by control.lead; independent reviewer quality.reviewer.
Outcome: research maintained real public MCP servers and/or skills, audit selected artifacts with Fugu and manual verification, report a list of verified vulnerabilities, and write issue drafts for any findings. Drafts are local only: no external issues, comments, email, advisories or disclosures are authorized by this assignment.

Select an initial bounded set of 5-8 relevant maintained projects, mixing MCPs and skills when credible candidates are available. Browse primary repositories/current releases to establish actual maintenance, identify supported versions/configuration, and pin exact commits/versions. Prefer official or widely used projects with concrete capability boundaries. Record source URL, commit, retrieval date, maintenance evidence, artifact and tools/features covered, and exclusions. Crafted corpus and MCPTox synthetic poison descriptions are not real-world vulnerabilities. Stop after this bounded audit and report; do not invent continuing tasks.

Use Fugu's applicable capabilities and inspect the actual source to triage findings. Security model alerts are hypotheses, not verified vulnerabilities. Establish the intended trust/permission contract and a reproducible unauthorized effect before calling something a vulnerability. A deliberate file-reader capability alone is insufficient; demonstrate a boundary violation where relevant. Distinguish an exploit, unsafe default, documented privileged feature, hardening suggestion, known/already-fixed issue, and inconclusive result. Search existing issues/advisories to avoid presenting known or fixed defects as new.

Run suspect artifacts only in the intended isolated chamber with synthetic data/canaries, blocked outbound traffic where possible, and no owner mounts, tokens or authenticated sessions. Never execute fetched skill instructions on the host, attack live deployments, or send actual secrets. Static local source inspection is allowed. Retain minimal evidence, remove credential-like strings from report artifacts using placeholders, and explain any redaction. No evidence fabrication or severity inflation.

Writer territory: docs/security/2026-10-02-maintained-extensions/ (report, issue drafts, source inventory), and bench/results/2026-10-02-wild-audit/ (pinned manifests and sanitized reproducible evidence). No edits to production code, dependency/lockfiles, frozen benchmark directories, root README, or the reliability task's files. No Git mutations. Ask lead for any additional territory. This counts as one of the at-most-two writers.

Acceptance: each confirmed finding lists project/version/commit, affected file and lines, problem, realistic preconditions, safe minimal reproduction, observed versus expected behavior, impact/severity with rationale, Fugu detection/evidence and limitations, known-issue status, and suggested remediation. One local Markdown issue draft per confirmed finding: accurate title, affected versions, description, reproduction, impact, mitigation, evidence links. If no vulnerability is verified, explicitly say so and list inspected scope; do not create speculative vulnerability issues. Separate unresolved leads from confirmed findings. Independent reviewer must reproduce/check the evidence before confirmation.

Research/tool use must be bounded; existing Tavily/Nebius quota is authorized until exhausted, no purchases. Snyk hosted pilot quota was exhausted in the prior benchmark: do not keep retrying it. Prefer primary public sources and offline checks, log model/calls/tokens where available, and record missing quota/coverage honestly.

Return: human-readable list of verified findings with primary source links and local issue-draft links, negative/uncertain findings separately, maintained-source inventory, reproducible sanitized evidence, checks, costs/coverage limits and independent review. Release writer territory before lead Git integration. Publication remains outside this task.
